# Tushare 2000 积分可用能力实测报告

> 探测时间：2026-10-05 23:55
> 探测方式：**对每个接口发真实请求**，看实际返回行数，不依赖官方文档推断
> 探测脚本：`research/scripts/probe_all_interfaces.py`
> 数据来源：Tushare Pro（token 存于项目根 `.env`，不落盘不进版本控制）

---

## 一句话结论

**27 个候选接口中 23 个可用（85%）。** 其中 6 个官方文档标注为高门槛的接口
实际也能取到——文档的保守标注低估了 2000 积分的实际权限。

**最具价值的发现**：本机 `stock_info` 表只有 8,409 行**单期快照**，
而 `daily_basic` 接口能提供 **1,448万行日频历史**。这是量级差异，
决定了本项目能否做时序因子检验。

## 三、不可用接口（4 个）

| 接口 | 原因 |
|---|---|
| `suspend_d` 停复牌 | 需更高积分 |
| `top_list` 龙虎榜 | 需更高积分 |
| `bak_daily` 日线备份 | 需单独权限 |
| `cyq_perf` 筹码分布 | 需 5000 积分 |

**影响评估**：
- 停复牌缺失 → 停牌日会表现为「无成交」，做活跃度因子时需按日期对齐处理
- 筹码分布缺失 → 无法做筹码结构类因子（如获利盘比例）
- 龙虎榜缺失 → 无法做游资席位因子

这三类在 A 股实证研究中都有价值，属于本次积分档位的**明确缺口**。
若后续升到 5000 积分，优先补 `cyq_perf`。

## 四、关键工程发现

### ① 按「交易日」批量拉，远优于按「股票」逐只拉

实测单日全市场 `daily_basic` 返回 **5,561 行 / 0.4 秒**：

| 方式 | 请求数 | 理论耗时 |
|---|---|---|
| 按交易日拉 `daily_basic` | 2,634 | 18 min |
| 按股票拉 `daily_basic` | 5,591 | 30 min |

行数完全一样，请求数差 2 倍以上。**日频类接口一律按交易日拉。**

### ② 但财务类接口**只能按股票拉**（实测推翻文档用法）

```
fina_indicator  {'period': '20240630'}  →     0 行
fina_indicator  {'ts_code': '600519.SH'} →   100 行  ✓
```

`period` 参数静默返回 0 行、不报错——这是最危险的一种失败模式。
三大报表（income / balancesheet / cashflow / fina_indicator / fina_mainbz / forecast）
全部实测确认必须用 `ts_code` 逐只拉。

⚠️ **AGENTS.md 已记录此坑**：接口静默返回空 ≠ 接口不可用，必须先试参数组合。

### ③ 部分接口支持报告期批量

```
stk_holdernumber  {'period':'20240630'}  → 5,500 行  ✓（一次拿全市场）
pledge_stat       {'quarter':'2024Q2'}   → 3,000 行  ✓
express           {'period':'20240630'}  →   100 行  ✓
```

这三个若按股票拉需 5,591 次，按报告期拉只需几十次，**差 100 倍**。

### ④ 限频是硬约束，实际耗时需按 0.52s/次估

实测 20 只股票耗时 10.7 秒 → 0.52 秒/只（含 180次/分钟限频等待）。
**按接口响应时间估算会低估 2.5 倍**，本项目所有预估已按实测口径修正。

## 五、数据量对照：本机 vs Tushare

| 数据 | 本机 SQLite | Tushare 补全后 | 差距 |
|---|---|---|---|
| 日线 | 1,646 万行（未复权） | 可替换为复权价 | **质量提升** |
| 估值/市值/换手 | 8,409 行（单期） | **1,448 万行（日频）** | **172 倍** |
| 行业分类 | 缺失 37.2% | 覆盖率 98.8% | **已解决** |
| 复权因子 | 无 | 140 万行 | **新增** |
| 财务三表 | 无 | 270 万行 | **新增** |
| 涨跌停 | 无 | 1,475 万行 | **新增** |
| 资金流 | 无 | 1,448 万行 | **新增** |
| 退市股 | 缺失（幸存者偏差） | 339 只 | **已补** |

**结论**：Tushare 2000 积分能补上的最大缺口是**估值/流动性因子的时序化**——
本机只有单期快照，无法做「估值分位随时间变化」这类最有价值的因子。

## 七、留待检验的假设

数据到手后需要实证检验，**以下都只是假设**：

1. **估值分位因子**（`daily_basic` 的 PE/PB 历史分位）—— 可能是最有效的估值因子
2. **现金流质量因子**（经营现金流 ÷ 净利润）—— 比净利润更难操纵
3. **筹码集中度**（`stk_holdernumber` 变动）—— 散户化程度
4. **股东风险偏好**（`pledge_stat` 质押率）—— 高质押股易暴跌
5. **卖方共识可能是反向指标**（`report_rc` 评级）——
   过度一致的预期已被 price in，需检验其 IC 是否为负

⚠️ 沿用本项目已有教训：**高 IC 等于高换手**。
`idio_vol_20` 的 ICIR = 0.639（全库最高）但年化净收益 −9.21%。
所有新因子必须先看净收益，再看 IC。
