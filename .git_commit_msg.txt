fix: 补声明 joblib 依赖 + 新增批量导入验证脚本

## ① 真实缺陷：joblib 是未声明的传递依赖

### 现象
目录重组重建 venv 后，4 个研究脚本连锁 import 失败：
  run_financial_study.py    ModuleNotFoundError: No module named 'joblib'
  expand_factor_library.py  同上（连带）
  holding_period_test.py    同上（连带）
  optimize_turnover.py      同上（连带）

### 根因
run_financial_study.py 用 joblib 做中性化的线程池并行
（实测 27.6s -> 8.8s，3.14x 加速），但 pyproject.toml 从未声明它 --
之前能跑是因为 akshare -> scikit-learn 把它间接带进来。
一旦换环境/重建 venv，传递依赖链一变就崩。

这是典型的「隐式依赖」陷阱：直接 import 的包必须显式声明。

### 修法
pyproject.toml 增补 "joblib>=1.4.0"，并注释说明为何必须显式声明。
uv sync 后 4 个脚本全部恢复正常。

## ② 新增 research/scripts/verify_imports.py

单进程内用 runpy 批量验证所有脚本的 import 链。

### 为什么需要它
逐个 `uv run xxx.py --help` 验证 17 个脚本要 5 分钟以上
（每次都要启动解释器 + 加载 pandas/numpy/scipy）。
改成单进程 runpy 后降到数秒，适合放进日常检查。

### 判定逻辑
  SyntaxError / ModuleNotFoundError / ImportError -> FAIL
  SystemExit（argparse 正常退出）                  -> PASS
  其他异常若出现在 main 阶段                       -> PASS（import 链已通）
  含网络调用的 3 个 fetch 脚本                      -> SKIP（只编译）

### 实测
  研究脚本 17 个：14 PASS / 3 SKIP
  工具脚本 16 个：16 PASS（编译检查）
  合计 30 通过 / 0 失败

## ③ 顺带确认
脚本间互相 import（expand_factor_library -> run_financial_study 等 5 处）
依赖的 sys.path 挂载在重组时已正确保留（parents[2] + parent 两条），
无需额外修改。
