## 关键技术发现（按重要性）

### 1. 年化口径错了252 倍（最严重）
`mean_return_by_quantile` 返回**每期**收益，原代码 `gross = spread * periods[0]`
而 `periods[0]=1`，于是打印成「年化」的值实际是**每日**差值。
修正为 `spread * (252 / periods[0])`。

影响：bp 从「年化净 0.0%」变成 **+3.2%**，ep 变成 **+6.1%**。
曾据此错误写出「扣成本后归零」的结论 —— 已全部更正到报告里。

### 2. 中性化退化成恒等变换，且输出一字不差
「行业 × 市值分位」分组去均值：A 股每行业股票少 → 每格约 2 只 →
组内去均值全压成 0.0 → 加 min_group 阈值 → 阈值把所有格子都保护掉 →
中性化变成恒等变换。⚠️ 最危险的是输出与原始因子**完全一致**，
极易误判为「中性化不影响结论」。实测 `changed frac == 0.0` 才发现。

改为逐日截面 OLS 残差（Barra 式）：`f = a + b·log(市值) + Σγ·行业哑变量 + ε`。

中性化前后对比（ICIR）：
| 因子 | 原始 | 中性化后 |
|---|---|---|
| bp | 0.174 | **0.330** |
| ep | 0.141 | **0.341** |
| roe | 0.039 | **0.159** |
| gross_margin | −0.005 | +0.047 |

→ 所有因子 ICIR 大幅上升，说明原始 IC 被行业/市值共同波动污染。

### 3. 财务披露延迟不能用固定天数
原用「报告期 + 45天」，对年报**提前 2.5 个月**（12-31+45=2/14，法定截止日次年 4/30）、
对半年报提前 17 天。改为按报告期类型取法定截止日。

### 4. 分层抽样
`codes[:200]` 按代码排序抽到全是 `bj4xxxxx` 北交所，与财务面板交集 0 而空跑。
改按 sh/sz/bj 分层抽样。

### 5. 性能：单线程 → 8 线程
本机 8 物理核/16 线程/13.9 GB。`neutralize` 按日拆分 + joblib 线程池
（不用进程池：每日是小矩阵 lstsq，numpy 释放 GIL；进程池要序列化 1000 万行）。
实测 2,724,494 行：27.6s → 8.8s（3.14x，结果逐元素一致）。
另把中性化结果缓存，避免主循环/子区间循环各算一遍。

**用户明确指出「硬件资源没有充分利用」——这条已写进 AGENTS.md 3.5 节。**

## Tushare 2000 积分能力实测 + Git 身份与分支规范化

### 一、Tushare 接口实测：23/27 可用

方法：不信文档，对每个接口发真实请求看返回行数。
脚本：`research/scripts/probe_all_interfaces.py`（探测 27 个接口，仅 3.2 秒）

| 分类 | 可用 | 内容 |
|---|---|---|
| P0 核心 | 6/6 | daily_basic / fina_indicator / 三大报表 |
| P1 增强 | 4/5 | stk_limit / moneyflow / index_daily / index_weight |
| P2 锦上添花 | 7/8 | trade_cal / stock_basic / hs_const 等 |
| P3 意外| 6/8 | forecast / express / fina_mainbz / report_rc / stk_holdernumber / pledge_stat |

**不可用4 个**：`suspend_d`（停复牌）、`top_list`（龙虎榜）、
`bak_daily`、`cyq_perf`（筹码分布，需 5000 积分）。

**关键发现 —— 本机数据的最大缺口是时序化**：
本机 `stock_info` 仅 8,409 行**单期快照**，
`daily_basic` 可提供 **1,448 万行日频历史** —— 172 倍量级差。
没有时序数据就无法构建「估值历史分位」这类最有价值的估值因子。

### 三个必须记住的 Tushare 坑

**① 静默失败：返回 0 行 ≠ 接口不可用**
```
fina_indicator  {'period':'20240630'}   →     0 行   ← 不报错，静默返空
fina_indicator  {'ts_code':'600519.SH'} →   100 行   ✓
```
三大报表全部只支持 `ts_code` 逐只拉。**任何接口首次使用必须先试 3~4 种参数组合。**

**② 批量拉取优先，请求数可差 100 倍**
日频类按交易日：5,561 行/次（2,634 次拿全历史）
可按报告期的（stk_holdernumber/pledge_stat）：5,500 行/次
→ 规则：先测 `{'period':...}` 返回多少行，为 0 就立刻改按 `ts_code`。

**③ 限频让耗时是接口响应时间的 2.5 倍**
限频 180 次/分钟 → 强制间隔 0.33s。实测按股票拉 20 只耗时 10.7s = 0.52s/只。
预估耗时要按0.52s/次算，否则低估一半（初版预估全错，已全部修正）。

完整报告：`docs/03_项目报告/11_Tushare2000积分可用能力实测.md`
补全脚本：`research/scripts/fetch_all_tushare.py`（P0 已在后台跑，约 3.5 小时）
