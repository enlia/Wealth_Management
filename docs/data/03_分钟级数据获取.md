# 分钟级数据获取指南

> 目标：拿到 A 股历史 1 分钟 / 5 分钟 K 线
> 调研时间：2026-10-02
> 关键结论：**本机通达信的分钟线只有约 2 个月，长期历史必须外部获取**

---

## 一、先看清代价：分钟级数据有多大？

实测本机通达信：**32 字节/根**，格式已逆向验证（见 `01_本机通达信数据资产.md`）。

| 周期 | 每年根数（单只） | 全市场 5500 只/年 | 10 年累计 |
|---|---|---|---|
| 1 分钟 | 250 日 × 240 根 = **60,000** | 3.3 亿根 | 33 亿根 = **105 GB** 原始 |
| 5 分钟 | 250 × 48 = **12,000** | 6,600 万根 | 6.6 亿根 = **21 GB** 原始 |
| 15 分钟 | 250 × 16 = 4,000 | 2,200 万根 | 7 GB |

**不同存储格式的体积差异**：

| 格式 | 1分钟 10 年 | 说明 |
|---|---|---|
| 通达信 .lc1 二进制 | 105 GB | 原始格式，体积最小 |
| SQLite（含索引） | ~160 GB | 查询快但占空间 |
| **Parquet + ZSTD** | **~20~30 GB** | ✅ **推荐归档格式**，压缩率高、列式读取快 |
| CSV | ~400 GB | ❌ 不要用 |

**结论**：分钟级数据是**存储敏感型**。如果你只想做日线级研究，**不要碰分钟级**。

## 二、免费方案

### ⭐ 方案 A：券商量化终端（最推荐，日线级玩家的最优解）

**QMT（迅投）/ PTrade（恒生）——软件本身完全免费**

| 项目 | QMT | PTrade |
|---|---|---|
| 软件年费 | **免费**（券商付费授权） | **免费** |
| 开通门槛 | MiniQMT：前 20 交易日日均资产 ≥ **10 万**；完整版更高 | 通常入金 ≥ 10~50 万免月租 |
| 开户方式 | **不能自助开通**，需联系持证客户经理加程序化白名单 + 签风险揭示书 | 同 |
| 运行方式 | **本地客户端**，代码在自己电脑跑 | **云端托管**，关机也能跑 |
| Level-2 | ❌ 默认不带，需另购 | ✅ 大多**自带免费 L2** |
| 投研版 | 约 **1 万元/年** | — |
| 适合 | 需要本地部署、策略开发 | 无运维能力、想 7×24 托管 |

**关键能力：客户端内置数据下载功能**
- QMT「行情 → 数据管理」界面，选代码、日期范围、周期（1分钟/5分钟/日线），直接下载到本地
- 之后通过 `xtdata.get_market_data()` 调用
- 数据源来自券商行情服务器，**质量有保障、免费且合法**

⚠️ **实操提醒**：
1. 下载全市场几千只 × 10 年分钟线，**占用空间极大**，建议只下载目标股票池
2. QMT 内置接口**默认给后复权**，自己下载的数据可能要手动处理复权
3. 建议先用日线验证逻辑，再逐级细化到分钟

### 方案 B：Baostock（零配置，但只到 60 分钟）

```python
import baostock as bs
bs.login()
# 支持 5/15/30/60 分钟线，历史深度稳定
bs.query_history_k_data_plus("sh.600519", "date,time,code,open,high,low,close,volume,amount", 
                              start_date='2024-01-01', end_date='2026-09-30', frequency="5")
```
✅ 优势：稳定、无需 token | ❌ 限制：**无 1 分钟线**

### 方案 C：efinance（零 key，但历史深度极短）

```python
import efinance as ef
ef.stock.get_quote_history("600519")   # 分钟级
```
❌ **硬伤**：1 分钟数据**仅能获取当天**；5 分钟数据**只有近 2 个月**。**无法用于长期回测**。

### 方案 D：Tushare（需 5000 积分，约 500 元）

```python
pro.stk_mins(ts_code='600519.SH', freq='1min', start_date='2025-01-01', end_date='2026-09-30')
# freq: 1min / 5min / 15min / 30min / 60min
```
- 5000 积分档解锁**分钟线 + 逐笔数据 + 龙虎榜**
- 数据结构规范，适合正式研究

### 方案 E：AlphaFeed（免费额度可试）

```python
from alphafeed import AlphaFeed
af = AlphaFeed()
af.klines.get("600519.SH", period="5m", count=48, to_dataframe=True)  # 历史分钟线
af.klines.intraday("600519.SH")        # 当日分时（今天到现在，约 240 根 1 分钟）
af.klines.intraday_batch([...])         # 多只批量
```
- period 支持 1m/5m/15m/30m/60m
- ⚠️ **历史回溯深度取决于套餐**

## 四、免费与付费的真实差距（容易被忽视）

| 维度 | 免费公开接口 | 付费数据 API | 自建行情管道 |
|---|---|---|---|
| 1 分钟历史深度 | 通常 **3~5 天** | **3~10 年** | 取决于自建存储 |
| 数据延迟 | 3~15 秒 | 1~3 秒 | 毫秒级 |
| **字段完整度** | 基础 OHLCV | OHLCV + **成交笔数** + **复权因子** | 全字段 + 委托队列 |
| 稳定性 | 无保障，随时变更 | 有 SLA | 取决于运维 |
| 调用限制 | 严格限频 | 按套餐 | 无 |
| 成本 | 免费 | 数千~数万/年 | 人力 + 服务器 |

**最容易被忽视的是"字段完整度"**：
- 免费接口的 1 分钟 K 线往往**只有 OHLCV，没有成交笔数**
- **成交笔数**在判断市场活跃度、做因子挖掘时很关键——比如"平均每笔成交量"因子，没有它算不出来
- **复权因子**更麻烦：免费接口通常只给不复权价，遇到除权除息日会跳空，**均线、MACD 全部失真**

## 五、给你的具体建议

### 判断题：先回答这三个问题

1. **你的策略持仓周期是几天还是几分钟？**
   → 几天 → **不需要分钟级**，用本机日线（已有 10.5 年）
   → 几分钟 → 才需要往下看

2. **你需要的分钟历史深度是多久？**
   → 日内策略至少 **1 年**（覆盖完整牛熊周期）
   → 少于 1 年的分钟数据做不出可靠结论

3. **你是否做日内择时？**
   → 否 → **明确不要碰分钟级**，成本远超收益

### 我给你的路径

**阶段 1（现在，0 成本）**：用本机通达信日线 + 周线做因子研究，**不要碰分钟级**

**阶段 2（日线策略跑通后）**：如果需要分钟级，先开一个 **10 万资金的券商账户拿 QMT/MiniQMT**，用客户端的数据下载功能拉目标股票池

**阶段 3（若做日内）**：买 Tushare 5000 积分（500 元）拿 5 年分钟线 + 复权因子

**明确不建议**：
- ❌ 个人做高频（需要毫秒级延迟 + L2 + 自建机房，收益覆盖不了成本）
- ❌ 买 L2 权限（多数人不需要）
- ❌ 用 efinance 做长期分钟回测（历史只有 2 个月）

## 六、存储方案建议

如果真的要存分钟级数据：

```
data/
├── minute_1m.parquet      ← ZSTD 压缩，列式，只存研究需要的字段
├── minute_5m.parquet
└── adj_factor.parquet     ← 复权因子，单独存
```

**关键设计**：
1. **只存需要的字段**：`date, time, code, open, high, low, close, volume, amount` — 去掉无用的
2. **分区存储**：按 `year/month` 或 `code_bucket` 分区，避免单文件过大
3. **Parquet + ZSTD** 而非 CSV/SQLite，压缩率差 5 倍以上
4. **复权因子单独存**，价格原始值 + 因子，查询时动态计算
