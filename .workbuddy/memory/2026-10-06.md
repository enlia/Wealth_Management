## 复权引擎收尾：判据三次推翻才收敛（Q1→Q2→Q4）

**背景**：上一轮留下的疑点是「全市场复权只消除 21.9%，与 300 只样本的 99.4% 矛盾」。
本轮查明：**两个数字都是错的**，复权引擎本身从一开始就是对的。

### 判据推翻链

| 版本 | 判据 | 为什么错 |
|---|---|---|
| v1 | 未复权 vs 后复权的累计收益之差 | 差额是**分红再投资价值**，不是偏差 |
| v2 | 固定容差 TOL=1.005 判超限 | 涨停价按 0.01 取整，真实涨幅超名义限幅，低价股最严重 |
| v3 | 价格相关动态容差 `price_tolerance()` | ✅ |
| v4 | + 封板交叉验证 + 新股无限幅窗口 | ✅ |

**核心教训：判据设计错误比代码 bug 更危险** ——
代码 bug 抛异常，判据错误安静输出一个看似合理的数字，还能用它确认后续所有结论。

### v2 的代价（关键数字）
`sz002426`（收盘 1.6~4.5 元）残留 31 条中 **27 条是 `close == high` 的真实封板涨停**，误判率 87%。
```
前收 2.66 → 涨停 2.93 = +10.15%   ← 固定 10.5% 容差判它超限
```
理论最大阈值（穷举 1.00~3000 元）：主板 **10.48%** / 双创 20.39% / 北交 30.48%。

### 漏掉的制度规则（Q4）
**注册制新股上市前 5 日不设涨跌幅限制**，三个板块生效日不同：
- 科创板 2019-07-22 / 创业板 2020-08-24 / **主板 2023-02-17（全面注册制）**

主板这条极易漏。只按「科创板/创业板」判定，会把11 条主板新股跳空误判成复权失败。
且必须传 `first_trade_date`：2023-02-17 前上市的主板新股第 2 日起就有限幅。

### 自身踩的坑
1. **pivot 面板行号 ≠ 交易日序号**（停牌处是 NaN）。
   `sz300873` 上市仅 3 个交易日，面板行号却是 1132 → 新股窗口判定完全失效。
   正解：`np.cumsum(np.isfinite(s))`
2. **诊断脚本自己会骗人**：临时脚本 `ffill` 未按 code 分组，跨股票对齐因子，
   得出「47,770 条复权失败」，引擎逐股重算实际是 **完全正确**的。
   → 定论前必须用第二套独立路径交叉验证（引擎重算 + `close == high` 封板特征）
3. `Decimal` 而非 `float + round`：银行家舍入与交易所四舍五入在 .005 奇偶位不一致，
   且 `0.1*1.1 = 0.11000000000000001` 偶发差一档
4. 容忍度价格下界不能从 0.01 元起：`round(0.011,2)` 是 0.01，
   加进位守卫后变 0.02 → 算出 **+100%** 荒谬阈值

