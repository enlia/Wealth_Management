   ```python
   "mom20": lambda d: momentum(d, 20, 0)    # = close[t]/close[t-20] - 1
   ```

## 四、成本敏感性：本报告最重要的一节

方法论步骤 6 明确指出：「**这一步决定实盘能不能赚钱**，很多研究在这一步就死了」。

### 先说清成本口径（这里很容易算错）

回测代码 `alphalens_adapter.py:218` 的实际公式：

```python
net = gross - cost.round_trip * turnover_mean * quantiles * periods_per_year
#= 毛收益 − 0.0020 × 单期换手 × 5分组 × (252 / 每期交易日数)
```

⚠️ **不是简单的「毛收益 ÷ 0.0020」**。实测反推**隐含系数 = 2.520**
（= 0.0020 × 5 × 252/1，即日频调仓），11 个因子中 10 个都是 2.520。

> ⚠️ **初版报告曾用 `毛收益/0.0020`（隐含系数 1.0），低估成本 2.52 倍**，
> 导致「rev5 只超了 16%」这种严重乐观的错误结论。正确是**超 14.7 倍**。
> ⇒ **成本类数字必须从代码口径反推，不能凭直觉估。**

### 盈亏平衡换手 = 多空毛收益 / 2.520

| 因子 | 多空毛收益 | **盈亏平衡单期换手** | 实际单期换手 | 判定 |
|---|---|---|---|---|
| **rev5** | +8.49% | **< 3.37%** | **49.42%** | ❌ **超 14.7 倍** |
| **rev20** | +10.19% | **< 4.04%** | **30.54%** | ❌ **超 7.6 倍** |
| amount20 | −31.00% | 永远不可能 | 4.14% | ❌ 毛收益本身为负 |
| vol60 | −9.42% | 永远不可能 | 5.29% | ❌ 毛收益本身为负 |
| downvol60 | −10.69% | 永远不可能 | 6.86% | ❌ 毛收益本身为负 |
| hhhl20 | −10.11% | 永远不可能 | 8.02% | ❌ 毛收益本身为负 |

**只有毛收益为正的 rev5 / rev20 值得讨论盈亏平衡，
而它们的换手分别超出盈亏平衡点 14.7 倍和 7.6 倍。**

其余 9 个因子毛收益本身就是负的，**换手再低也救不回来** ——
这是「方向错了，参数调不出来」的情形。

### 换手率的单位（初版报告标注错误）

`summary.csv` 里的「平均换手」是**单期**换手，不是年换手：

| 口径 | rev5 | rev20 | 全样本均值 |
|---|---|---|---|
| 单期换手 | 49.42% | 30.54% | **18.76%** |
| 折算年换手（×252） | 124.5 倍/年 | 77.0 倍/年 | **47.3 倍/年** |

⇒ 年换手 47~125 倍，**达到方法论里「日频策略年换手 125 倍 = 年成本 37.5%」的红线量级**。

### 为什么 A 股尤其致命

方法论里那张表讲的是"日频策略在散户费率下数学上不可能盈利"。本报告实测印证了这一点，
而且 A 股的约束**更严**：

- **T+1 制度**：当日买入不能卖出，无法做日内回转
- **涨跌停**：最强的那些票往往买不进（本轮 `limit_state` 尚未接线，见第七节）
- **融券成本高**：8%+ 且券源稀缺，多空组合实盘不可行

⇒ 即便某个因子的多空净收益为正，**散户也无法用多空组合吃到它**。

### 一个待查的异常

`hhhl20` 的隐含系数是 **1.512**，其余 10 个因子都是 2.520。
按 ENGINEERING.md「异常值必须做反证」，此处**尚未追查**，
可能与该因子的分组数或调仓频率处理不同有关。列入遗留问题。

## 六、口径缺陷修复记录（本轮）

子agent review 报出 3 个 BLOCK，逐条复核后**全部成立**，已修复并配守护测试。
更重要的是：**我写守护测试时又抓出一个 review 都没发现的 bug**。

| 编号 | 缺陷 | 实测影响 |
|---|---|---|
| **B1** | `np.clip` 发生在哨兵置 0 **之后**，把 0 抬成 `min_weight` | 哨兵槽权重 **0 → 6.25%**，凭空建仓 |
| **B2** | `_year_span` 注释声称有"天数下限"，**代码里根本没有** | 20 交易日 +8% 被报成 +183% 年化 |
| **B3** | 基准比策略**多算 1 天**，且该日收益来自训练期 | 基准年化偏高 **1.44pp**，所有超额被低估 |
| **B4**（自测抓出） | 哨兵映射到列 0，而列 0 **本身就是真实持仓**；散射赋值后写覆盖 | 真实持仓 c0 权重 **0.6 → 0**，日收益 +0.2% → −0.4% |
| **B5**（自测抓出） | `T = r_mat.shape[0]` 假设 fwd 与 dates 等长 | 生产路径恰好等长，**bug 一直藏着** |

> **B4 比 B1 更隐蔽**，也更值得记住：`-1 → 0` 这个映射"看起来"已经处理了哨兵，
> 但 `0` 不是一个空列，它是一只有真实价格的股票。
> numpy 散射赋值对重复下标是**后写覆盖**，不报错、不告警。
>
> **教训**：修哨兵类问题时，"用 0 代替 -1" 这种修补会制造新的、更难发现的 bug。
> 正确做法是**给哨兵一个专属的、真实数据里不存在的垃圾列**。

修复后新增 `tests/test_review_2026_10_06.py`（18 个断言），
每条都设计成「**还原 bug 版会失败**」——橡皮章测试等于没测。
全套 **234 passed**。

## 八、给手动交易者的可执行结论

### ❌ 不要做的事

1. **不要用任何价量/技术形态因子直接选股**。11 个全市场实测，扣成本后净收益无一为正。
2. **不要相信"IC 0.04 听起来不小"**。IC 0.04 在扣成本后是 −116%/年。
3. **不要用多空组合**。A 股散户无法做空，本报告的多空口径只用于衡量因子预测力。

### ✅ 应该做的事

1. **降低换手是唯一的免费午餐**。本报告里换手最低的 `amount20`（4.1%）虽然毛收益为负，
   但成本拖累只有 −10.4pp，是全部因子里最小的。**低频 = 少交学费**。
2. **若一定要用反转因子，务必拉长持仓期**。rev5（5日）换手 49%，
   rev20（20日）单期换手 30.54% —— 后者成本拖累只有前者的 62%（−77.0pp vs −124.5pp）。
   5 日反转在 A 股扣成本后是**不可能盈利**的。
3. **本项目的实证结论是：价值因子（bp）是唯一三段扣成本后净收益全正的因子**
   （+1.0%/+7.1%/+2.2% 年化，ICIR 0.330，见项目已有结论）。
   价量因子这条路已经走到头了，**要转向基本面/价值因子**。

## 九、口径声明（引用本报告前必读）

1. **多空组合不可实盘**：A 股散户无法做空融券（成本 8%+、券源稀缺），
   多空口径仅用于衡量因子预测力。
2. **幸存者偏差已处理**：窗口内退市股15 只全部补齐行情与复权因子，敞口 0.268% → 0。
3. **市值单位**：统一为**万元**，`check_units.py` 校验与 Tushare 误差 ≤ 0.0002%。
4. **未做多重比较校正**：11 个因子 × 3 个子区间 = 33 次检验。
   即便全部显著，按 5%显著性水平也预期有 1.65 个假阳性。
   **本报告的结论不依赖显著性，而依赖"净收益全部为负"这一方向的绝对量级。**
   另需注意 `mom20` 与 `rev20` 互为相反数，**实际独立检验只有 10 个**，
   报成 11 个会高估证据量。
5. **滑点假设**：单边 0.1%，属**乐观估计**。真实滑点随流动性差异极大，
   小盘股实际可达 0.3%+。若用更差的滑点，净收益只会更负。

## 附录：残留超限归因复算 SQL（2026-10-06）

上文「残留超限归因口径」快照表的复算 SQL，market.db 只读直查。
口径与 `factor_lab.market_rules` 对齐：涨跌停价按**整数分四舍五入**
（SQLite `round()` 对 .005 中点的舍入与交易所规则不一致，会把真实封板
误判成超限，故显式实现半入）；收益为面板 `pct_change` 语义（缺口不跨日）；
新股无限幅窗口同 `no_limit_days()`；`board_pre` 一处为修复前板块口径
（302 段误判主板 ±10%）的对照。

```sql
WITH a AS (
  SELECT code, date, close, close_adj,
         CASE
           WHEN code LIKE 'bj%' THEN 'bse'
           WHEN code LIKE 'sh688%' OR code LIKE 'sh689%' THEN 'star'
           WHEN code LIKE 'sz300%' OR code LIKE 'sz301%' OR code LIKE 'sz302%' THEN 'gem'
           ELSE 'main'
         END AS board
  FROM bar_daily
  WHERE date BETWEEN 20160101 AND 20260930
    AND (
      code LIKE 'sh6%'
      OR code LIKE 'sz0%'
      OR (code LIKE 'sz3%' AND code NOT LIKE 'sz399%')
      OR code LIKE 'bj4%'
      OR (code LIKE 'bj8%' AND code NOT LIKE 'bj88%')
      OR code LIKE 'bj92%'
    )
),
cal AS (
  SELECT date, LAG(date) OVER (ORDER BY date) AS gprev
  FROM (SELECT DISTINCT date FROM a)
),
base AS (
  SELECT a.code, a.date, a.close, a.close_adj, a.board, cal.gprev,
         LAG(a.close)     OVER (PARTITION BY a.code ORDER BY a.date) AS pc0,
         LAG(a.date)      OVER (PARTITION BY a.code ORDER BY a.date) AS pdate,
         LAG(a.close_adj) OVER (PARTITION BY a.code ORDER BY a.date) AS pa,
         ROW_NUMBER()     OVER (PARTITION BY a.code ORDER BY a.date) AS td,
         FIRST_VALUE(a.date) OVER (PARTITION BY a.code ORDER BY a.date) AS first_date,
         MIN(CASE WHEN a.close_adj IS NOT NULL THEN a.date END)
           OVER (PARTITION BY a.code) AS first_adj,
         SUM(CASE WHEN a.close_adj IS NOT NULL THEN 1 ELSE 0 END)
           OVER (PARTITION BY a.code) AS n_adj
  FROM a JOIN cal ON cal.date = a.date
),
f AS (
  SELECT base.*,
         CASE board WHEN 'bse' THEN 0.30 WHEN 'star' THEN 0.20
                    WHEN 'gem'  THEN 0.20 ELSE 0.10 END AS lim,
         CASE board WHEN 'bse' THEN 20211115 WHEN 'star' THEN 20190722
                    WHEN 'gem'  THEN 20200824 ELSE 20230217 END AS reg_start,
         CASE WHEN pdate = gprev AND pa IS NOT NULL AND close_adj IS NOT NULL
              THEN close_adj / pa - 1 END AS ret_adj,
         CASE WHEN pdate = gprev AND pc0 IS NOT NULL AND pc0 > 0 AND close IS NOT NULL
              THEN close / pc0 - 1 END AS ret_q,
         CASE WHEN pdate = gprev AND pa IS NOT NULL AND close_adj IS NOT NULL
              THEN 1 ELSE 0 END AS ret_adj_defined,
         -- 容差 = price_tolerance 复刻：涨停价整数分半入 + 半档 tick 余量
         CASE WHEN pc0 > 0
              THEN (CAST((CAST(pc0 * 100 + 0.5 AS INTEGER)
                            * (100 + CASE board WHEN 'bse' THEN 30 WHEN 'star' THEN 20
                                                WHEN 'gem'  THEN 20 ELSE 10 END) + 50) / 100
                         AS INTEGER) / 100.0 / pc0 - 1 + 0.005 / pc0) END AS tol,
         CASE WHEN pc0 > 0
              THEN (CAST((CAST(pc0 * 100 + 0.5 AS INTEGER)
                            * (100 + CASE WHEN code LIKE 'sz302%' THEN 10
                                          WHEN board = 'bse' THEN 30 WHEN board = 'star' THEN 20
                                          WHEN board = 'gem'  THEN 20 ELSE 10 END) + 50) / 100
                         AS INTEGER) / 100.0 / pc0 - 1 + 0.005 / pc0) END AS tol_pre
  FROM base
),
g AS (
  SELECT f.*,
         (CASE WHEN board = 'bse' THEN td <= 1
               WHEN first_date < reg_start THEN td <= 1
               ELSE td <= 5 END) AS in_window,
         (CASE WHEN code LIKE 'sz302%' THEN
                 (CASE WHEN first_date < 20230217 THEN td <= 1 ELSE td <= 5 END)
               WHEN board = 'bse' THEN td <= 1
               WHEN first_date < reg_start THEN td <= 1
               ELSE td <= 5 END) AS in_window_pre,
         (ret_adj IS NOT NULL AND abs(ret_adj) > tol AND pc0 > 0
           AND NOT (CASE WHEN board = 'bse' THEN td <= 1
                         WHEN first_date < reg_start THEN td <= 1
                         ELSE td <= 5 END)) AS over_adj,
         (ret_adj IS NOT NULL AND abs(ret_adj) > tol_pre AND pc0 > 0
           AND NOT (CASE WHEN code LIKE 'sz302%' THEN
                          (CASE WHEN first_date < 20230217 THEN td <= 1 ELSE td <= 5 END)
                        WHEN board = 'bse' THEN td <= 1
                        WHEN first_date < reg_start THEN td <= 1
                        ELSE td <= 5 END)) AS over_adj_pre
  FROM f
),
h AS (
  SELECT g.*,
         (CASE WHEN NOT over_adj THEN 'ok'
               WHEN ret_q IS NULL THEN 'undetermined'
               WHEN abs(ret_q) > tol THEN 'both_over'
               ELSE 'adj_only' END) AS bucket,
         (CASE WHEN NOT over_adj_pre THEN 'ok'
               WHEN ret_q IS NULL THEN 'undetermined'
               WHEN abs(ret_q) > tol_pre THEN 'both_over'
               ELSE 'adj_only' END) AS bucket_pre
  FROM g
)
SELECT board,
       COUNT(*) AS n_rows,
       SUM(ret_adj_defined) AS n_ret,
       SUM(CASE WHEN n_adj >= 2 AND date = first_adj THEN 1 ELSE 0 END) AS n_first_day,
       SUM(over_adj)  AS n_over,
       SUM(CASE WHEN bucket     = 'both_over'    THEN 1 ELSE 0 END) AS both_over,
       SUM(CASE WHEN bucket     = 'adj_only'     THEN 1 ELSE 0 END) AS adj_only,
       SUM(CASE WHEN bucket     = 'undetermined' THEN 1 ELSE 0 END) AS undetermined,
       SUM(over_adj_pre) AS n_over_pre,
       SUM(CASE WHEN bucket_pre = 'both_over'    THEN 1 ELSE 0 END) AS both_over_pre,
       SUM(CASE WHEN bucket_pre = 'adj_only'     THEN 1 ELSE 0 END) AS adj_only_pre,
       SUM(CASE WHEN bucket_pre = 'undetermined' THEN 1 ELSE 0 END) AS undetermined_pre
FROM h
GROUP BY board
ORDER BY board
```
