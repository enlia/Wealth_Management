### 1. 核心行情库 `market.db`（2.6 GB）

SQLite 单文件，含 10 张表：

| 表 | 行数 | 说明 |
|---|---|---|
| `bar_daily` | 16,476,179 | 日线（含 `close_adj` 前复权 qfq 价） |
| `bar_weekly` | 3,487,632 | 周线 |
| `stock_info` | 8,728 | 股票基本信息与财务快照 |
| `sector` | 547 | 行业分类 |
| `sector_member` | 69,878 | 行业成分 |
| `ts_income` | 323,973 | 利润表（金额已转亿元） |
| `ts_balance_sheet` | 267,494 | 资产负债表（金额已转亿元） |
| `ts_cashflow` | 292,429 | 现金流量表（金额已转亿元） |
| `ts_fina_indicator` | 248,605 | 财务指标 |
| `ts_top10_holders` | 257,987 | 十大股东 |

**关键口径（必须一起带走，缺了结论会变）**：
- 复权：`close_adj = close × factor(t) / factor(最新日)`，基准日 **2026-09-30**
- `bar_daily.date` 是 **int**（YYYYMMDD），不是字符串
- Tushare 表的日期列已统一归一为 **int32**
- **单位换算按字段类别，不要一刀切**（一刀切会差 1e4~1e8 倍且不报错）：
  - 财务三表（`ts_income` / `ts_balance_sheet` / `ts_cashflow`）**金额列**：
    Tushare 原始【元】，并库入口 `merge_tushare_tables.normalize()` 统一
    × `YUAN_TO_YI = 1e-8` 转【亿元】。换算哪些列不是关键词猜的 ——
    由 `build_money_whitelist.py` 从真实 parquet 推导
    （`runtime/tushare/_money_whitelist.json`），显式排除每股指标、比率、
    增速、天数、周转率、股本列；实测换算列数 income 72 /
    balance_sheet 140 / cashflow 88 / fina_indicator 0
    （各表 `{表}_meta` 记录口径）。
  - **每股指标**（eps / bps / cfps / `*_ps`）：【元/股】，**不换算**。
  - **股本** `ts_balance_sheet.total_share`：【股】（只读实测
    600519 2026-06-30 = 1,250,081,601，对应约 12.5 亿股），排除换算。
  - **市值**（`stock_info.mktcap` 等）：统一【万元】（`MARKET_CAP_UNIT`）——
    `universe.csv` 的「亿元」列在 `build_sqlite.py` 入口经 `to_wan()` ×1e4
    转万元；Tushare `total_mv` / `circ_mv` 本身就是万元，不再换算。
  - **行情** `bar_daily`：`amount`【元】、`vol`【股】（只读反推
    `amount/(vol×close)` 3 日抽查 = 0.99~1.00），不参与金额换算。
  - ⚠️ 边界：未入库的原始 parquet 字段口径与上表不一定相同
    （如 `daily_basic.circ_mv` 是万元，见 `UNITS.md` U1 与
    `run_size_decile.py` 的反推记录）；用任何量纲存疑的字段前先找已知真值
    反推验证，别照搬「一律 ×1e-8」。
  - 量纲抽证（market.db 只读查询，2026-10-07）：`stock_info.net_assets`
    2,512.536 亿元 ÷ `shares` 12.500815 亿股 = 200.9898 元/股
    = `ts_fina_indicator.bps` 200.9898 ✅

**覆盖范围**：2015-09-14 ~ 2026-09-30，5,606 只 A 股，
`close_adj` 非空 10,852,754 行（覆盖率 98.384%）。

## 三、明确排除的内容及理由

### `runtime/backup/`（17 GB，8 个 .db）

迁移过程的临时快照（`before_unit_fix`、多个时间戳）。
最新完整库是 `data/market.db`，备份可删。

**建议：删除以释放 17 GB 磁盘。**若需保留可读性，
只留最近一个即可 —— 但对网盘上传来说一个都不必传。

### `runtime/tushare_backup_pre_datetype/`（2.4 GB）

日期列类型迁移（string → int32）前的备份，
对应的新文件已在 `runtime/tushare/` 中。**纯冗余**。

### `moneyflow.parquet`（895 MB）与 `daily_basic.parquet`（691 MB）

合计占 tushare 目录的 69%，但：

- **`moneyflow`（资金流）**：当前因子研究未使用。需要时可按日期重下。
- **`daily_basic`（每日指标）**：市值分层检验用过`circ_mv`，
  但同样是 `by_date` 模式可重下，1,118 万行约 20 分钟。

**若你要在离线机器上复现市值分层检验**，把 `daily_basic` 也传上
（包体积 +约 200 MB 压缩后）。

### `runtime/` 下的日志与临时文件

`*.log`、`*_smoke/`、`diag*.log` 等，体积小但无保留价值。

## 四、恢复步骤

### 1. 解压主库

```bash
7z x market_db.7z -o./
# 或 tar（若打成 tar.gz）
tar -xzf market_db.tar.gz
```

得到 `data/market.db`（约 2.6 GB）。

### 2. 校验数据完整性

```bash
uv run python -c "
import sqlite3, pandas as pd
con = sqlite3.connect('file:data/market.db?mode=ro', uri=True)
r = pd.read_sql('''SELECT MIN(date) d0, MAX(date) d1,
                         COUNT(DISTINCT code) nc, COUNT(*) nr
                  FROM bar_daily WHERE close_adj IS NOT NULL''', con).iloc[0]
print(f'bar_daily: {r.d0}~{r.d1}  {r.nc} 只  {r.nr:,} 行')
"
```

**期望输出**：
```
bar_daily: 20150914~20260930  5606 只  10,852,754 行
```

若行数不一致，说明文件损坏或版本不对。

### 3. 校验数据版本

```bash
uv run python research/scripts/data_version.py --show
```

**期望数据版本**：`871a003e6d5e`
（53 张 tushare 表 / 4,818 万行）

若版本号不同，说明上传的库与本地当时的库不一致。

### 4. 解压 Tushare 子集

```bash
7z x tushare_subset.7z -o./runtime/
```

### 5. 安装 Python 环境（uv，与 pyproject.toml / uv.lock 对齐）

```bash
# Python 3.12 是依赖链硬约束（<3.13：peewee 3.17.3 在 3.13 下构建失败）
uv python pin 3.12
uv sync --frozen --extra dev
```

⚠️ **不要 `pip install` 裸装**：装出来的版本与 `pyproject.toml` / `uv.lock`
不一致，正是「隐式依赖 → 4 个研究脚本连锁 ModuleNotFoundError」的复现路径
（P1 / ENGINEERING §六「依赖必须显式声明」）。依赖清单以 `pyproject.toml`
为准，本文不再手列包名。

### 6. 跑测试确认环境正常

```bash
uv run pytest tests/ -q
# 期望：257 passed, 6 warnings
# 数字口径：2026-10-07 实测，项目 .venv（uv sync 后）的 python
# -m pytest tests/ -q（全量 tests/）
```
