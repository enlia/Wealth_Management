# MEMORY.md · 长期项目笔记

## 用户画像（通达信投研会话）

- A 股个人投资者，通过通达信 MCP 连接器做选股与技术形态筛选。
- **能力水平**：能提出「日线 + 周线双周期共振」这类进阶筛选条件，也会主动质疑工具有效性（曾问「黄金分割有道理吗、经过市场验证吗」；本次会追问「硬件资源没有充分利用」）。
  但同时会回头追问基础术语（H / L / HH / HL、什么是支撑位），说明其知识结构是「**会用工具但概念未成体系**」：能凭直觉操作，但缺少严格定义。
  → **答复策略**：使用专业术语时必须随手给出简要定义，不可默认用户已掌握；概念讲解要配图 + 大白话释义。
- **短板**：风险管理。提问习惯集中在「给我能赚钱 / 大大概率赚钱的股票」，极少涉及仓位规模、止损执行与交易复盘。
- **表达偏好**：要求结论明确、给出可执行价位（买点区间、止损线、目标位）；接受坦率直白的风险提示，不需要客套。
- **内容深度要求（重要）**：用户两次明确嫌内容太浅。要求**底层原理 + 数学推导 + 可验证算例**，可以长、可以信息密度高，但**不允许泛泛而谈或说教式罗列**。
- **案例必须用真实行情（重要）**：禁止使用「假设某策略胜率 55%」这类抽象模型。案例必须取自通达信真实数据——**具体股票代码 + 具体日期 + 具体价格**，用户会自行复核。做教程时应主动拉取真实 K 线数据作为素材。
- **呈现要求**：图文并茂，每个知识点配图（SVG/图表）；新概念先给「大白话解释」再展开；篇幅要足，宁长勿短。用户明确表示「华丽花哨但没实际内容没意义」。**但也曾明确说「不要浪费时间做无用功，比如 html 网页」——所以优先纯文字/Markdown，图表用内联SVG，不要做 HTML 页面。**
- **效率敏感（2026-10-05 新增）**：会检查资源利用率。**长任务必须并行化，不要单线程跑全市场**；跑之前先 profile 找瓶颈。

## 协作约定

1. 荐股答复**必须同时包含**：止损位（跌破即离场的具体价格）、仓位建议、板块集中度风险。只给标的代号视为不合格。
2. 数据一律标注来源（通达信）与截止日期；休市期间必须写明「数据截至 YYYY-MM-DD 收盘」。
3. 所有投资相关结论结尾声明「不构成投资建议」。
4. 用户容易把「这只会不会赚钱」作为唯一目标，需主动把讨论拉回**期望值 / 赔率 / 风险控制**的框架。
5. **写报告时必须附带口径声明**（见 AGENTS.md 第八节）：多空组合口径（A 股散户无法做空）、幸存者偏差、市值用当前股本快照、未做多重比较校正。

## 检验框架铁律（2026-10-06 滚动检验确立，最高优先级）

**这批规则的违反会造成「结论看起来很好但实为运气」，比代码 bug 危害更大。**

| 规则 | 具体要求 |
|---|---|
| **禁用单次样本切分** | 一律用 `run_walk_forward.py` 的滚动窗口（测试段两两不重叠）。切点决定结论：rev5 的「样本外+27.92%」是2023 后单边行情里的单一窗口，滚动检验下7 窗口只赢 4个 |
| **混淆检验必做** | 因子收益可能全部来自风格暴露。用 `run_size_decile.py` 按流通市值分层，**层内用层内自己的基准**。rev5 就是靠这个才被否掉的 |
| **两脚本数字冲突时先查基准** | 基准一致说明窗口对，差异必在策略区间。实测两脚本同一因子年化差 10 倍（漏写 `.loc[te]`） |
| **质量门禁必须扫真实文件** | 不能只查代码是否正确。`moneyflow` 在修复后仍是 string（运行中的进程不获得代码修复），只有扫真实文件的测试抓到 |
| **判据是分布不是均值** | 胜率≥60% / 超额中位数>0 / 最差窗口>−5%，且窗口数≥5。单窗口的胜率只有 0% 与 100% 两种取值，阈值对它无约束力 |
| **参数扫描后必须核对数值是否真变** | 完全相同 = 死参数不是「稳健」。`n_pick` 曾是死参数，扫描表 12 组数值两两相同却看起来「高度稳健」 |
| **年化口径全项目统一** | 用自然日（`/365.25`），**禁止 `len/252`**（252 是美股口径，A 股 243~245）。策略与基准必须共用 `_year_span()` |
| **收益必须从价格算** | 不能从因子值算。z 分数比值无意义，会出年化波动 33,494% 的结果 |
| **新模块提交前必须跑真实数据** | `tradability.py` 提交时三个函数全坏、零测试覆盖，而它的存在意义就是消除静默偏差 |
| **价格口径：PB 用未复权、收益用前复权** | 2026-10-06 血泪。一个面板不能同充当两个角色：`bps/eps` 是财报披露的原始数字（配未复权价），收益必须用前复权。污染量实测**5~17pp/年**，大于任何因子收益。`load_prices` 的 `field` 已取消默认值 —— 漏写口径要抛 TypeError |
| **`close_adj` 是前复权(qfq)，不是后复权** | 实测 `adj/close` 末日恒 = 1.000000（茅台 0.793056→1.000000）。⚠️ **qfq 每遇分红送转就整体重算历史 ⇒ runtime/ 的历史结论不可复现，引用必须带数据版本戳**。项目内 86 处表述已纠正 |
| **测试全绿 ≠ 代码能跑** | 批量替换把 `{ind}` 占位符写进 3 个脚本造成 SyntaxError，而 `pytest` 报 350 passed —— 因为测试从不 import `research/` 下的脚本。已补 `compile()` 语法门禁 |
| **正则守卫是橡皮章，扫描类门禁用 AST** | review 实测位置参数 `load_prices(c,s,e,"close")` 与 `field=VAR` 两种绕过全通过。**取消 API 默认值 > 写门禁**（门禁代替不了设计） |

**静默失效三类（每类都真实踩过）**：
1. 类型不匹配 —— 日期列存成 string，`df[df.d == 20240102]` 恒返回 0 行且不报错
2. 索引/代码口径不一致 —— `ts_code` 交易所是**后缀**不是前缀，交集为 0 而约束 100% 失效
3. 诊断输出本身错—— `len(DataFrame)` 返回列数，因子面板每年打印「1 格」实为 1,460 万格

| 结论 | 证据强度 |

| **rev5（5日反转）判定不可用 —— 收益来自市值暴露，不是信号** | 全市场 5,606 只 × 7 窗口。~~层内超额：大盘 +0.95%(4/7)、中盘 −0.89%(3/7)、小盘 +5.19%(5/7)~~ **❌ 2026-10-06 作废**（分层时点用了窗口末日市值=按结果分组）；修正为层内超额中位 **大盘 −14.79% / 中盘 −8.15% / 小盘 +0.86%**，大盘层为正窗口仅 1/7 |
