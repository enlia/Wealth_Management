## 复权引擎收尾：判据三次推翻才收敛（Q1→Q2→Q4）

**背景**：上一轮留下的疑点是「全市场复权只消除 21.9%，与 300 只样本的 99.4% 矛盾」。
本轮查明：**两个数字都是错的**，复权引擎本身从一开始就是对的。

### 判据推翻链

| 版本 | 判据 | 为什么错 |
|---|---|---|
| v1 | 未复权 vs 后复权的累计收益之差 | 差额是**分红再投资价值**，不是偏差 |
| v2 | 固定容差 TOL=1.005 判超限 | 涨停价按 0.01 取整，真实涨幅超名义限幅，低价股最严重 |
| v3 | 价格相关动态容差 `price_tolerance()` | ✅ |
| v4 | + 封板交叉验证 + 新股无限幅窗口 | ✅ |

**核心教训：判据设计错误比代码 bug 更危险** ——
代码 bug 抛异常，判据错误安静输出一个看似合理的数字，还能用它确认后续所有结论。

### v2 的代价（关键数字）
`sz002426`（收盘 1.6~4.5 元）残留 31 条中 **27 条是 `close == high` 的真实封板涨停**，误判率 87%。
```
前收 2.66 → 涨停 2.93 = +10.15%   ← 固定 10.5% 容差判它超限
```
理论最大阈值（穷举 1.00~3000 元）：主板 **10.48%** / 双创 20.39% / 北交 30.48%。

### 漏掉的制度规则（Q4）
**注册制新股上市前 5 日不设涨跌幅限制**，三个板块生效日不同：
- 科创板 2019-07-22 / 创业板 2020-08-24 / **主板 2023-02-17（全面注册制）**

主板这条极易漏。只按「科创板/创业板」判定，会把11 条主板新股跳空误判成复权失败。
且必须传 `first_trade_date`：2023-02-17 前上市的主板新股第 2 日起就有限幅。

### 自身踩的坑
1. **pivot 面板行号 ≠ 交易日序号**（停牌处是 NaN）。
   `sz300873` 上市仅 3 个交易日，面板行号却是 1132 → 新股窗口判定完全失效。
   正解：`np.cumsum(np.isfinite(s))`
2. **诊断脚本自己会骗人**：临时脚本 `ffill` 未按 code 分组，跨股票对齐因子，
   得出「47,770 条复权失败」，引擎逐股重算实际是 **完全正确**的。
   → 定论前必须用第二套独立路径交叉验证（引擎重算 + `close == high` 封板特征）
3. `Decimal` 而非 `float + round`：银行家舍入与交易所四舍五入在 .005 奇偶位不一致，
   且 `0.1*1.1 = 0.11000000000000001` 偶发差一档
4. 容忍度价格下界不能从 0.01 元起：`round(0.011,2)` 是 0.01，
   加进位守卫后变 0.02 → 算出 **+100%** 荒谬阈值

## 子agent review 拦下 5 个阻塞项（全部修复）

**评审机制有价值**——它找出的问题全在我「以为已经验证过」的地方。

### ① 布尔取反把「排除」写成了「计入」（最严重）

```python
# ❌ 原代码
ok = ret.abs() <= tol
ok &= ~np.array([no_limit_days(...)])
return ~ok          # 窗口内 → ok=False → 判超限
```
新股无限幅窗口的意思是「这天再涨也不算超限」，是**排除**。
写成 `~` 再取反，效果与注释**完全相反**。

**注意：不能简单改成 `&= no_limit_days()`**——那样窗口外的日子会全判超限。
正确写法是让排除作用在「超限」上：
```python
# ✅
over = np.abs(ret) > tol
over &= np.logical_not(in_window)
return over
```
实测代价：200 只样本 13 条「规则内超限」中 11 条是窗口内日子被误计。

⚠️ 附带发现：`~` 作用在 numpy bool 数组上是**按位**取反，
Python 3.16 起已废弃，必须用 `np.logical_not`。

# 第二轮：滚动样本外检验（接续上文「三个年化数字矛盾」的排查）

## 起点：三个数字其实自洽，不是 bug

上文的疑问是「全期 0.71% vs 样本外 27.92%」。**先验算再找 bug**：

```
0.9222^7.52（样本内 -7.78%/年） × 1.2792^3.22（样本外 +27.92%/年） = 1.2019
→ 全期年化 +1.73%
```

三者数学自洽。真正的 bug 在别处。

**教训**：看到几个数字「矛盾」时，先做复利连乘验算确认是否同一口径，
不要立刻去找 bug。可能是自己的口径混用了。

## 决定性结论：单次 70/30 切分不能作为因子可用性证据

新建 `factor_lab.analysis.walk_forward`，7 个滚动窗口（测试段两两不重叠）：

| 测试窗口 | 策略 | 基准 | 超额 |
|---|---|---|---|
| 2019 | 10.37% | 31.92% | -21.55% |
| 2020 | -2.93% | 21.14% | -24.07% |
| 2021 | 34.96% | 26.94% | +8.02% |
| 2022 | 3.77% | -10.87% | +14.64% |
| 2023 | 19.80% | 11.27% | +8.54% |
| 2024 | 33.71% | 5.79% | +27.92% |
| 2025 | 39.89% | 40.15% | -0.26% |

**胜率 4/7（57%），最差 -24.07% ⇒ rev5 不可用。**

那个「样本外 +27.92%」是 2023 下半年之后单边上涨行情里的**单一窗口**，
恰好是 7 个窗口里最好的一个。**切点决定了结论**。

判据是「超额的分布」不是均值：胜率≥60% / 中位数>0 / 最差>-5%。
均值的缺陷：单窗口 +200% 能把 10 个 -10% 的均值拉到正数。

## 修的实质缺陷（都是判据级，不是代码 bug）

### 1. n_pick 死参数（最隐蔽）
`held_mat = top_idx[:, :n_hold]`，而 top_idx 已按因子降序排好，
前 n_hold 个元素与 n_pick 毫无关系。
参数扫描表「候选池大小」列 12 组数值**两两完全相同**，
年化 21%~37% 看起来「高度稳健」—— 那是假象。

根因不是算错，是**缓冲带语义根本没写**，只写了「取前 n_hold」。
新增 `factor_lab.analysis.selection`：持仓股只要还在 top n_pick 内就不卖。
修复后换手随候选池变宽单调下降 0.0401 → 0.0165。

### 2. 日期列全库 52 张表存成 string
Tushare 返回 '20240102' 字符串，`to_parquet` 原样存 string，
`df[df.trade_date == 20240102]` 恒返回 0 行**且不报错**。

第一轮枚举 13 个字段迁了 20 张表，
**review 复扫发现还漏 5 个**（in_date 涉及 29 张表），
根因是「靠人肉枚举必然漏」→ 加兜底规则：
列名匹配 date 且类型是 string/float 时也纳入，排除 update_flag。

另：`normalize_types` **不幂等** ——
Int32 含 NA 时强转 numpy int32 抛 `cannot convert NA to integer`，
对已迁移的表再跑就崩。

### 3. 诊断打印用 len(df) 冒充形状
`len(DataFrame)` 返回**列数**，因子面板每年打印「1 格」，
实际有 1,460 万格。一度被误判为「面板损坏、跨年拼接失效」。
必须用 `.shape` —— 且 acc[f] 是**列表**，元素才是 DataFrame，
写 `x.shape` 会 AttributeError（我改错了一次）。

## review 找出的：我的结论本身有偏置

子 agent review 报 3 BLOCK + 6 MAJOR。其中 **M1 直接影响我报出的数字**：

策略侧年化用自然日（364/365.25），基准侧用 `len/252`（261/252=1.036）。
同一份收益两个年化，**基准被低估约 0.5pp/年**，
而「超额 = 策略 - 基准」是全部结论的判据。

252 是**美股**口径，A 股实际约 243~245 个交易日。
统一为自然日口径，抽 `_year_span()` 作为唯一实现。

重跑后数字微调但判定不变（最差 -24.85% → -24.07%）。

### tradability.py 三个函数提交时全是坏的（零测试覆盖）
- `ts_code.str.slice(0,2)` 把交易所当**前缀**，
  实测与本机代码**交集为 0** —— 约束 100% 失效且不报错
- `trade_date` 被自己的迁移改成 int32 后，字符串比较直接 TypeError
- 补位从全市场取而非候选池 → **因子信号在这一步被丢弃**
  （注释写「用候选池补位」，但函数根本没收到候选池）

**教训**：新模块提交前必须真的跑一次真实数据。
「测试全绿」不等于「新模块可用」—— 此模块当时零测试覆盖。

### fillna(True) 根本不触发
`close >= NaN` 返回 **False**（不是 NaN），
所以涨跌停价缺失的格子被当成「未封板」= 可随意买卖。
连 fillna 的兜底都失效。

### 封板率 37% 是假象
真实 2023 年真封涨停率 **0.50%**，整体 37% 里 32% 是「缺数据被当不可交易」。
分板块：沪主板 0.41% / 深市 0.61% / 北交所 0.29%（都正常）。
新增 `coverage_report()` 强制分板块报告 ——
不拆开就会得出「A 股三分之一的日子在涨停」的错误结论。

rev5 选出的小盘股均价 11.37 元，比全市场便宜 36.7% ——

|---|---|---|---|

| 超额胜率 | 4/7 | 3/7 | 5/7 |

**结论：层内超额三项全部不达标。**
rev5 跑赢基准的收益**主要来自小盘市值暴露**，不是反转信号。

## 今天最关键的方法论教训

**分层场景下必须用「层内自己的基准」。**

大盘层绝对收益 +37.22% 看着很美，但大盘层自己的基准在 2019/2021
就涨了 +45.22% / +36.27% —— 那是牛市，不是因子选股好。
用全市场基准比，会把「牛市里大盘涨得多」误读成「因子在大盘上有效」。

**同一份数据，两个口径，结论完全相反。**
