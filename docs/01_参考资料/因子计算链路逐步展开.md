## 一、数据从哪来

### 表结构

```sql
CREATE TABLE bar_daily (
    code       TEXT,     -- 本机代码格式，如 'sh600519'
    date       INTEGER,  -- YYYYMMDD，如 20240830
    open       REAL,     -- 开盘价（元，未复权）
    high       REAL,     -- 最高价（元，未复权）
    low        REAL,     -- 最低价（元，未复权）
    close      REAL,     -- 收盘价（元，未复权）
    close_adj  REAL,     -- 后复权收盘价（元）★ 因子只用这个
    vol        REAL,     -- 成交量（股）
    amount     REAL      -- 成交额（元）
);
```

| 项 | 数值 |
|---|---|
| 总行数 | 16,476,179 |
| `close_adj` 非空行数 | 10,852,754 |
| 覆盖 A 股比例 | 98.384% |
| 时间范围 | 2015-09-14 ~ 2026-09-30 |
| 股票数 | 5,606 只 |

### 一行真实数据（sh600519 茅台 2024-08-30）

```
code       date        open    high     low     close    close_adj        vol        amount
sh600519   20240830    1413.00  1458.07  1405.00 1443.19  1338.6516543873923.0   5576118784.0
```

⚠️ **`close` 和 `close_adj` 差 7.2%**（1443.19 → 1338.65），
这就是复权因子 0.927564 的作用。

## 二、第 1 步：复权（为什么必须做）

### 公式

```
close_adj = close × factor(t) ÷ factor(最新日)
```

### 实测验证

茅台 2024 年 8 月的复权因子**恒为 0.927564**（因为基准日固定为 2026-09-30）：

| 日期 | close | close_adj | 复权因子 |
|---|---|---|---|
| 20240812 | 1436.10 | 1332.075223 | 0.927564 |
| 20240820 | 1422.72 | 1319.664411 | 0.927564 |
| 20240830 | 1443.19 | 1338.651654 | 0.927564 |

### 不用复权会怎样

除权日会出现**假跳空**——公司分红送股，股价从 100 变50但股东没损失。

实测：未复权价算出 **0.291% 的单日收益超过 ±10% 涨跌幅限制**，
年化偏差 2.33pp（`DATA_QUALITY.md` Q1）。

### 关键设计：为什么同时保留未复权 OHLC

`load_long` 返回**两套价格**：

- `close` / `high` / `low`（未复权）→ 用于**涨跌停判定**与**仙股过滤**
  （交易所约束的是报价，与复权无关）
- `close_adj` / `high_adj` / `low_adj`（后复权）→ 用于**因子计算与收益计算**

`high_adj` 由 `high × close_adj ÷ close` 推导——
复权是乘性调整，同一天三个价格位共用同一个乘数。

## 三、第 2 步：算因子原始值（11 个因子的全部公式）

以 `rev5` 为例，茅台 2024-08-30：

```
close_adj[t]   = 1338.651654   （20240830）
close_adj[t-5] = 1312.494339   （20240823）

近5日涨幅 = 1338.651654 ÷ 1312.494339 − 1 = +0.019929
rev5 因子值 = −(+0.019929) = −0.019929        ← 注意取负号
```

### 全部 11 个因子

| 因子 | 公式 | 用到的字段 |
|---|---|---|
| `mom20` | `close_adj[t] / close_adj[t-20] − 1` | close_adj |
| `mom60_skip20` | `close_adj[t] / close_adj[t-80] − 1` | close_adj |
| `mom120_skip20` | `close_adj[t] / close_adj[t-140] − 1` | close_adj |
| `rev5` | `−(close_adj[t] / close_adj[t-5] − 1)` | close_adj |
| `rev20` | `−(close_adj[t] / close_adj[t-20] − 1)` | close_adj |
| `vol60` | `std(日收益, 60日) × √252` | close_adj |
| `downvol60` | `std(仅负收益, 60日) × √252` | close_adj |
| `volratio5_60` | `mean(vol, 5日) / mean(vol, 60日)` | vol |
| `amount20` | `mean(amount, 20日)` | amount |
| `pos250` | `(close − min250) / (max250 − min250)` | close_adj |
| `hhhl20` | `[high20[t] > high20[t-20]] + [low20[t] > low20[t-20]]` | high_adj, low_adj |

### 三个必须解释的参数

**① `skip` 为什么存在**

`mom60_skip20` 的分母是 **t−80** 而不是 t−60。

A 股 T+1 制度下，日内动量与隔夜动量**方向相反、相互抵消**。
学术研究指出必须跳过最近约 1 个月，否则信号被抵消。

**② `√252` 是什么（年化倍数）**

波动率年化属于**年化换算三分层**的①倍数换算层：**倍数换算 = 252**
（每期收益→年化 ×252/periods、波动 ×√252、成本 ×252）。
另两层各管各的语义：②无日期索引的兜底年跨越 = 交易日数 ÷ 243（年均交易日）；
③有日期的年跨越 = 自然日 365.25（年数按日期跨度算）。
三个常数互不替代、不按市场分家 ——
`std(日收益, 60日) × √252` 得到年化波动率。

⚠️ 实现现状（如实记录）：`price_volume.py:130`/`:149` 及 `src/tools/`
三处的年化乘数现取 `× √244`，与 ① 层常数偏差约 **1.63%**（√(252/244)）；
因子随后做横截面 z 标准化，排序不受影响，但原始波动率数值口径受影响 ——
代码改动另行安排。

**③ `vol60` 的方向陷阱**

`vol60` 分数高 = **波动率最大的股票 = 高风险股**，
不是「稳健股」。

回测取「分数最高的 30 只」= 集中买波动最大的股票。
**如果想买入低波动股，应当取分数最低的 30 只**——
但当前框架没有实现「取最低」这个方向。

**④ `pos250` 的真实算例**（茅台 20240830）

```
250 日最低 = 1280.03
250 日最高 = 1608.54
pos250 = (1338.65 − 1280.03) ÷ (1608.54 − 1280.03) = 0.1784
```

含义：股价在近一年区间里处于**偏低位置**（离谷底近、离山顶远）。

## 四、第 3 步：横截面标准化

### 公式

```
z[i,t] = ( factor[i,t] − mean(t) ) / std(t)
```

`mean(t)` / `std(t)` 是**当天全市场**的均值和标准差，逐日滚动。

### 实测（20240830 截面）

```
当天有 rev5 值的股票数 = 5,308
原始值 mean = −0.034941   std = 0.051121

茅台 rev5 = −0.019929
茅台 z = (−0.019929 − (−0.034941)) ÷ 0.051121 = +0.2936
茅台排名 = 第 1803 / 5308名
```

**同日排名前 8 名**：

| 代码 | rev5 原始值 | z 分数 |
|---|---|---|
| sh600187 | +0.319892 | **+6.94** |
| sz000755 | +0.261460 | +5.80 |
| bj920175 | +0.226250 | +5.11 |
| sz300050 | +0.210031 | +4.79 |
| sz300949 | +0.195755 | +4.51 |
| sz300775 | +0.183037 | +4.26 |
| sh688187 | +0.182394 | +4.25 |
| sh600650 | +0.181611 | +4.24 |

### 为什么必须每天独立算

不同年份市场风格不同（2017 小盘占优 vs 2020 大盘），
全样本统一标准化会让**因子含义随时间漂移**，样本外必然失效。

### 性能说明

初版用 `groupby(level=0).transform(z)`，
5,600 列 × 2,611 行跑不出来（groupby 在宽表上极慢）。
改成按行 numpy 广播：均值/标准差都是 `(T,1)`，与 `(T,N)` 一次广播完成。

## 五、第 4 步：收益计算（为什么必须 `shift(-1)`）

### 时序约束

```
因子用d 日【收盘价】算出→ d 日收盘后才能知道 → 最早 d+1 日买入
```

所以收益必须用**下一期**：

```python
fwd = price_panel.pct_change(fill_method=None).shift(-1)
```

### 用错会怎样

`sh600187`（20240830 排名第一）的真实日收益：

| 日期 | close_adj | 当日收益 | 次日收益 |
|---|---|---|---|
| 20240827 | 3.020 | −4.305% | −10.035% |
| 20240828 | 2.890 | **−10.035%** | −2.692% |
| 20240829 | 2.600 | −2.692% | +6.324% |
| 20240830 | 2.530 | −2.692% | +6.324% |
| 20240902 | 2.690 | +6.324% | −3.717% |

若错用 8-30 的**当日**收益 +3.042%（8/29→8/30），
等于「在信号产生前就赚到了」—— 策略收益会被系统性虚高。

### 顺带发现：涨跌停约束的必要性

`sh600187` 在 8/23~8/29 连续出现 −9.95%、−9.85%、−4.31%、−10.04%、−2.69%。

这不是普通下跌，是**连续跌停**。实盘含义：
- 跌停时**卖不掉**（想跑跑不掉，风险敞口被迫延续）
- 后续反弹时**买不进**（信号失效，等下一轮就是一周后）

所以 `tradability.py` 建模了涨跌停约束——
但**尚未接入回测主流程**，意味着当前收益率**可能高估**。

## 六、第 5 步：选股与组合构建

### 参数

| 项 | 值 |
|---|---|
| 持股数 `n_hold` | 30 只 |
| 候选池 `n_pick` | 90 只（= 3 × n_hold） |
| 调仓频率| 月频（每月首个交易日） |
| 权重 | 波动率倒数（风险平价思路的简化版） |
| 单票权重 | 裁剪到 2% ~ 15% |
| 年换手 | 约 8.8% |
| 年成本 | 约 3.6% |

### 实测（2024-09-02 截面）

```
当天有 rev5 值的股票数 = 5,308

第 30 名 z = +2.8442← 买入门槛
前 90 名（候选池）门槛 z = +2.0614 ← 缓冲区边界
```

### 候选池缓冲带（`n_pick`）的真实作用

**规则**：已持仓的股票只要还在前 90 名内就继续持有，
只有跌出前 90 的槽位才用池内下一顺位的新股票补。

**为什么需要它**：某只股票从第 32 名升到第 28 名（因子值只差 0.01），
没有缓冲带就要卖出再买回，白付两次成本。

**修复前后的差别**：

| n_pick | 单次调仓换手 |
|---|---|
| 30（无缓冲） | 0.0401 |
| 90 | 0.0405 |
| 150 | 0.0365 |
| 300 | 0.0264 |

⚠️ **修复前 `n_pick` 是死参数**：`held = top_idx[:, :n_hold]`，
而 `top_idx` 已按因子值降序排好，前 n_hold 个元素与 n_pick 毫无关系。
参数扫描表里「候选池大小」那一列 12 组数值**两两完全相同**，
看起来「高度稳健」—— 那是假象。

## 七、第 6 步：从排名到结论

### 回测结果（滚动样本外，7 个窗口）

| 指标 | rev5 实测值 |
|---|---|
| 年化收益中位 | +19.80% |
| 超额中位（vs 小盘等权基准） | +8.02% |
| 超额胜率 | 4/7（57%） |
| 最差窗口 | −24.07% |
| 最大回撤 | −33.69% |
| 年换手 | 8.76% |
| 年成本 | 3.63% |

**口径四要素**（P14：缺一会导致方向性误读，本表每个数字都按下述口径）：

| 要素 | 口径 |
|---|---|
| 年化口径 | 年化换算**三分层**（各常数管各语义、勿一刀切）：① 倍数换算 = 252（每期收益→年化 ×252/periods、波动 ×√252、成本 ×252）；② 无日期索引的兜底年跨越 = 交易日数 ÷ 243（年均交易日）；③ 有日期的年跨越 = 年数按日期跨度 = 自然日 365.25（`_year_span`）。本表数字的年数跨度取 ③ |
| 成本假设 | 「年化收益」是**扣成本后**净值的年化（`net = gross − cost`）；成本模型 `factor_lab.analysis.long_only.CostModel`：买 0.126% / 卖 0.176%（佣金万 2.5 + 过户费十万分之一 + 滑点 0.1%，卖出另加印花税 0.05%）；表中「年成本 3.63%」是窗口内实测年均成本 |
| 基准 | 股票池**等权**买入持有收益（`price.pct_change().mean(axis=1)`，窗口内重算、无换手无成本）；股票池是分层抽样样本即「样本池等权」，是全市场即「全市场等权」。等权隐含小盘暴露（本文「小盘等权基准」的说法由此而来），等权 vs 市值加权基准差异可达 8pp 量级（PITFALLS P14）——「超额」全部按本行基准计算 |
| 多空/多头 | **单边多头**（只能做多），不是多空组合 |

### 然后是决定性的第7 步：混淆检验

rev5 选出的股票均价 11.37 元，比全市场便宜 36.7%——
它选的就是小盘股。而等权基准本身就是「小盘等权」。

按流通市值分层，用**层内自己的基准**：

| 分层 | 层内超额 | 胜率 |
|---|---|---|
| 大盘层 | +0.95% | 4/7 |
| 中盘层 | −0.89% | 3/7 |
| 小盘层 | +5.19% | 5/7 |

**三项全部不达标 → rev5 的收益来自市值暴露，不是反转信号。**

⚠️ **绝对收益与层内超额给出完全相反的结论**：

| 口径 | 大盘层 | 中盘层 | 小盘层 |
|---|---|---|---|
| 绝对收益 | +37.22% | +24.76% | +13.31% |
| 层内超额 | +0.95% | −0.89% | +5.19% |

大盘层绝对收益高，是因为**它所在的 2019/2021 是牛市**
（大盘层自己的基准就涨了 +45.22% / +36.27%）。

## 八、一个关键问题：11 个因子的信息量远小于 11

### 实测相关系数（2024-12-30 截面，1,099 只样本）

| | mom20 | rev5 | rev20 | vol60 | hhhl20 | amount20 |
|---|---|---|---|---|---|---|
| **mom20** | 1.00 | −0.66 | **−1.00** | −0.66 | 0.52 | 0.27 |
| **rev5** | −0.66 | 1.00 | 0.66 | 0.53 | −0.26 | −0.15 |
| **rev20** | **−1.00** | 0.66 | 1.00 | 0.66 | −0.52 | −0.27 |
| **vol60** | −0.66 | 0.53 | 0.66 | 1.00 | −0.29 | −0.13 |
| **hhhl20** | 0.52 | −0.26 | −0.52 | −0.29 | 1.00 | 0.17 |
| **amount20** | 0.27 | −0.15 | −0.27 | −0.13 | 0.17 | 1.00 |

**`mom20` 与 `rev20` 相关系数 = −1.00** ——
它们是**同一个信号取反**，不构成两个独立维度。

### 11 个因子用到的原始字段只有 5 个

```
close_adj / high_adj / low_adj / vol / amount
```

**完全没有涉及**：
- 估值（pe / pb / ps / 市值）
- 盈利（roe / 净利率 / 毛利率）
- 成长（营收增速 / 净利增速）
- 财务健康（负债率 / 现金流）
- 资金流（北向/ 主力净流入）
- 行业分类

**所以「11 个因子」的真实信息量远小于 11**：
它们都是「过去 N 天价格或成交量的滚动统计量」，
同一族信息，换了窗口和符号而已。
把 5 个字段喂进去、套 6 种数学变换，
**不可能凭空造出估值/盈利维度的信息**。

## 九、本轮发现并修复的缺陷

### 跨年预热链有 4 处断点 🔴 静默丢数据

用户追问「因子计算是否太简单」时，我顺手查了 `pos250` 的覆盖率，
发现它是**0.0%**。逐年排查发现 4 个独立缺陷——
**每一个都不报错，只是安静地丢掉预热数据。**

#### 断点 1：预热天数按自然日算

```python
#❌ 初版
ts = pd.Timestamp(d) - pd.Timedelta(days=260)     # 260 自然日 ≈ 173 交易日
# ✅ 修复
ts - pd.tseries.offsets.BDay(260)                   # 260 交易日
```

`pos250` 需要 **250 个交易日**，自然日只给 173 个 ⇒ 少 77 天。

实测：`_shift_date('20240101', -260)` 返回 `20230416`，
正确应是 `20230102`。

#### 断点 2：下界被 `max()` 夹回本年元旦

```python
lo = max(ys, start[:8])      # ❌ start 是预热起点，会被夹回元旦
lo = start[:8]               # ✅ 它已是更早的预热起点
```

#### 断点 3：首年完全不预热 ⭐ 最隐蔽

```python
if y > y0: pad_start = _shift_date(ys, -WARMUP_TRADING_DAYS)
else:      pad_start = ys                    # ❌ 首年无预热
```

实测 `build_panel(..., '20190101', '20191231')`：
- `pos250` 覆盖率 **0.0%**
- `mom120_skip20` 覆盖率 7.5%

长窗口因子在首年必然大面积 NaN，
表现为「因子没数据」，很容易被误判成「该股不合格」。

#### 断点 4：算因子前就裁掉预热行 ⭐ 真正根因

```python
# ❌ 先裁剪，再算因子
long = long[(long["date"] >= lo) & (long["date"] <= hi)]   # 预热行在这里没了
s = compute_factor(f, long)                                 # 因子看不到预热

# ✅ 先去重 → 再算因子 → 最后裁剪
```

#### 修好 1~3 后暴露的连带问题

`years` 按 `pad_start` 实际落点算后，相邻年份段的预热区间**会重叠** ——
同一 `(code, date)` 出现两次，`unstack` 直接抛
`ValueError: Index contains duplicate entries`。

必须在算因子之前去重（`_prep` 内部排序但**不去重**）：

```python
long = (long.sort_values(["code", "date"], kind="stable")
            .drop_duplicates(subset=["code", "date"], keep="last"))
```

实测去重前后：`962 → 683 行`，`pos250` 覆盖率 `0.0% → 13.3%`（300 只样本）。

### 为什么这类缺陷最难发现

| 特征 | 说明 |
|---|---|
| 不报错 | 所有代码路径都正常执行 |
| 不抛异常 | 因子值就是 NaN，看起来像「数据缺失」 |
| 不影响短窗口因子 | `rev5` 只回看 5 日，缺 77 天预热影响很小 |
| 整体覆盖率正常 | 全期 72.1% 看着正常，掩盖了 pos250 的 0.0% |

**教训：修复「样本量不足」类问题时，把每个断点单独修完再验证** ——
修好一个只暴露下一个，不通读代码根本发现不了断点 1 和 2 的存在。
